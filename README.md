# Bodymake Nutrition App

食事管理を通じて理想の身体づくりをサポートするWebアプリ

## 1. サービス概要

本サービスは、食事管理を通じて理想の身体を目指す人に向けたWebアプリである。

ユーザーの身長・現在の体重・目標体重・目標体脂肪率・生活スタイルなどをもとに、1日の摂取カロリーや栄養素の目安を提示する。また、目標に合った食材や料理を提案し、食事の記録・栄養素の自動集計・進捗の可視化を通じて、理想の身体づくりをサポートする。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

筋トレを始めて毎日の食事管理をするようになり、体重や体脂肪率を気にするようになった。

食事のたびに食品のカロリーやタンパク質量を検索し、1日の摂取量を計算していたが、毎回調べて計算することを面倒に感じていた。

また、理想の体重や体脂肪率から逆算して、必要な食事内容や摂取カロリー、栄養素などを提示してくれるサービスがあれば便利だと感じた。

### 2-2. なぜそれが「気になった」のか

私が体重や体脂肪率、食事の栄養管理を気にするのは、理想の体になって、魅力的な男性になりたいからだ。

理想の身体に近づくためには、運動だけでなく日々の食事にも気を配りたいと考えている。そのため、摂取カロリーや栄養素を把握し、効率よく食事管理を行える方法があればよいと感じた。

## 3. 課題の整理

### 3-1. 表に見えている困りごと

- 食事のたびに食品のカロリーや栄養素を調べる必要がある。
- 食べた量に応じて栄養素を計算し、1日の合計を把握するのに時間がかかる。
- 理想の身体を目指すために、どのくらいのカロリーや栄養素を摂取すればよいのか分からない。
- 必要な栄養素を摂取するために、どのような食材や料理を選べばよいのか分からない。
- 過去の食事内容を振り返りにくく、自分の食事管理が適切なのか不安になる。

### 3-2. 本当に解決したい課題は何か

**なぜ1：** 食事のカロリーやPFCを把握するには、食品を検索し、食べた量を入力して栄養量を確認する必要があるから。

**なぜ2：** 同じ食品や食事を繰り返し食べても、毎回検索・入力するのは手間がかかるから。

**なぜ3：** よく食べる食品や過去の食事を簡単に再利用できなければ、記録に時間がかかり、食事管理を続けにくくなるから。

**なぜ4：** 食事記録が途切れると、1日の摂取カロリーやPFC、目標に対する進捗を把握しにくくなるから。

**本当に解決したい課題：**

理想の身体を目指す人が、自分の目標に合った摂取カロリーやPFCを把握しにくく、食品検索や食事入力の繰り返しによって、食事管理を継続しにくいこと。

**この課題に対する解決方針：**

基礎代謝量や身体活動レベルなどから摂取カロリーの目安を推定し、目標体重に応じて初期目標を設定する。現在の体脂肪率と目標体脂肪率は記録して推移を可視化し、目標との差を確認できるようにする。また、お気に入り食品、最近使った食品、前日の食事コピーによって入力操作を減らす。食事の自動集計と進捗表示を組み合わせ、少ない手間で目標への取り組みを振り返れるようにする。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

**ターゲット：** 食事管理を通じて理想の身体を目指している人。

筋トレやダイエットなどの目的にかかわらず、体重や体脂肪率などの目標に向けて食事管理に取り組みたいと考えている人を対象とする。

特に、自分に必要な摂取カロリーや栄養素が分からず、どのような食材や料理を選べばよいのか迷っている人や、毎日の栄養計算に負担を感じている人を想定する。

**抱えている課題**

- 理想の身体を目指すにあたり、1日にどのくらいのカロリーや栄養素を摂取すればよいのか分からない。
- 必要な栄養素を摂取するために、どのような食材や料理を選べばよいのか分からない。
- 食品ごとのカロリーや栄養素を調べて計算することに時間がかかる。
- 過去の食事内容や栄養摂取量を把握できず、適切に食事管理できているのか不安を感じる。

**アプリが提供する価値**

ユーザーの目標や生活スタイルに応じて栄養管理の目安を提示し、食材・料理の提案、食事記録、栄養素の自動集計、進捗の可視化を通じて、理想の身体づくりをサポートする。

### 4-2. 自分とユーザーの距離

**自分自身**

今回のアプリの想定ユーザーは、自分自身でもある。

私自身、筋トレを始めて体重や体脂肪率を意識し、毎日の食事管理を行う中で、食品のカロリーやタンパク質量を調べ、1日の摂取量を計算することに時間がかかり、負担を感じている。

自分自身がこの悩みを抱えているからこそ、食事管理の手間を減らし、理想の身体づくりを継続しやすくするサービスを作りたい。

### 4-3. 実際に使われる可能性について（需要・存在確認）

**最初に使ってくれそうな人**

筋トレをしていて、食事管理も行っている友人。

**現在の食事管理方法**

友人は、頭の中でおおよその摂取カロリーや栄養素を計算している。

**友人が感じている課題**

- 過去にどのような食事をしたか覚えていられない。
- 頭の中で栄養素を計算するのが大変。
- 必要な栄養素を適切に管理できているのか不安がある。

**利用意向の確認**

食べた食品と量を記録することで、1日の摂取カロリーや栄養素を自動計算でき、過去の食事も振り返れるアプリについて、友人から「使ってみたい」という回答を得た。

**現時点での仮説**

食事記録と栄養素の自動集計、過去の食事履歴の確認ができれば、食事管理の手間や不安を減らせる可能性がある。今後、実際の利用を通じて検証したい。

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ

**1. サービスを知るきっかけ**

筋トレやダイエットなどを始め、本格的に食事管理に取り組もうとしたときに、Googleで「筋トレ 食事管理 カロリー計算」などと検索してサービスを知ることを想定する。

**2. 初回利用時の流れ**

ユーザーは、年齢、基礎代謝量の推定式に用いる性別区分、身長、現在の体重、現在の体脂肪率、目標体重、目標体脂肪率、生活スタイル、身体活動レベル、運動習慣などを登録する。初期版では、18〜79歳の成人を対象とする。

登録情報をもとに、1日の目標摂取カロリーとPFC（タンパク質・脂質・炭水化物）の目安を確認する。これらは推定値として提示し、利用者が目標を確認できるようにする。

**3. 日々の利用方法**

食べた食品を登録済みの食品データから選択し、摂取量を入力する。入力した内容から、1日の摂取カロリーとPFCを自動集計する。

**4. 継続利用の仕組み**

日々の食事記録に加え、体重や体脂肪率などの記録と目標に対する進捗をグラフで確認できるようにする。進捗に応じたメッセージも表示し、ユーザーが成果や変化を振り返りながら食事管理を続けられるようにする。

そこで、摂取カロリー・PFCの目安と実際の摂取量を比較できるようにし、体重・体脂肪率の進捗確認と、繰り返し食べる食品を簡単に記録できる機能を組み合わせたサービスを作りたい。

**ユーザーが得られる体験**

この体験が目標の理解や記録の継続に役立つかは、今後、競合アプリの実際の画面や機能を比較し、想定ユーザーからのフィードバックを通じて検証する。

## 7. このアプリで実現すること

### 7-1. MVPで作る機能

まずは以下の5つの機能に絞り、目標設定から食事記録、進捗確認までを少ない操作で行えるようにする。

1. **ユーザー情報・目標の登録**

   年齢、基礎代謝量の推定式に用いる性別区分、身長、現在の体重、現在の体脂肪率、目標体重、目標体脂肪率、身体活動レベル、運動習慣などを登録する。初期版では18〜79歳の成人を対象とする。

2. **摂取カロリー・PFCの目安の提示**

   基礎代謝量と身体活動レベルから1日の摂取カロリーの目安を推定する。現在の体重と目標体重を比較して減量・維持・増量の方向を判断し、初期目標を設定する。また、目標摂取カロリーをもとにタンパク質・脂質・炭水化物（PFC）の目標量を提示する。現在の体脂肪率と目標体脂肪率は、摂取カロリーの計算には直接使用せず、記録と進捗表示に活用する。

3. **食事の記録と入力操作の簡略化**

   登録済みの食品を選択し、食べた量や食事のタイミングを記録する。入力の手間を減らすため、次の機能を設ける。

   - **お気に入り食品：** よく食べる食品をお気に入りに登録し、食事記録からすぐに選択できるようにする。
   - **最近使った食品：** 過去に記録した食品を、最近使ったものから再選択できるようにする。
   - **前日の食事コピー：** 前日の食事記録にある食品・摂取量・食事タイミングを当日にコピーできるようにする。当日の既存記録は削除せず、コピー内容を追加する前に確認できるようにする。

4. **カロリー・PFCの自動集計**

   食事記録から1日の摂取カロリーとPFCを自動計算し、目標値と実際の摂取量を比較できるようにする。

5. **進捗表示・モチベーションサポート**

   体重・体脂肪率・摂取カロリー・PFCの記録をグラフで表示する。体重と体脂肪率は現在値と目標値との差や推移を確認できるようにし、進捗に応じたメッセージも組み合わせて、食事管理を継続しやすくする。

### 7-2. 計算方法と食品データの出どころ

**1. 基礎代謝量と摂取カロリーの推定方法**

基礎代謝量の推定には、厚生労働省「日本人の食事摂取基準（2025年版）」に掲載されている国立健康・栄養研究所の推定式を採用する。体重をW（kg）、身長をH（cm）、年齢をA（歳）とする。

- 男性：基礎代謝量（kcal/日）＝（0.0481×W＋0.0234×H－0.0138×A－0.4235）×1000÷4.186
- 女性：基礎代謝量（kcal/日）＝（0.0481×W＋0.0234×H－0.0138×A－0.9708）×1000÷4.186

この式の妥当性が確認されている年齢幅は18〜79歳である。初期版では成人を対象とし、計算値は推定値として表示する。

推定した基礎代謝量に身体活動レベルを掛け、維持に必要なエネルギー量を推定する。

推定維持エネルギー量（kcal/日）＝基礎代謝量（kcal/日）×身体活動レベル

MVPでは、現在の体重と入力された目標体重を比較し、目標体重が現在の体重より低い場合は減量方向、高い場合は増量方向、同じ場合は維持方向とする。減量方向は推定維持エネルギー量の90％、維持方向は100％、増量方向は110％を仮の係数として、摂取カロリーの初期目安を算出する。

この係数は試作上の仮定であり、個人に最適な摂取量や目標達成を保証するものではない。推定値であることを明示し、利用者が目標や摂取目安を確認・調整できる設計とする。

現在の体脂肪率と目標体脂肪率は、摂取カロリーの計算式には直接使用しない。両方を記録し、現在値と目標値の差（パーセントポイント）や推移を画面・グラフで確認できるようにする。

**2. PFCの目標量の設定方法**

初期設定では、総摂取エネルギーに占める割合を、タンパク質20％、脂質25％、炭水化物55％とする。これはMVPの仮設定であり、ボディメイクに最適な比率と断定せず、今後検証する。

目標摂取カロリーをE（kcal）とした場合、各栄養素の目標量を次のように計算する。

- タンパク質（g）＝E×0.20÷4
- 脂質（g）＝E×0.25÷9
- 炭水化物（g）＝E×0.55÷4

計算では、タンパク質と炭水化物を1gあたり4kcal、脂質を1gあたり9kcalとして換算する。初期設定の妥当性は、公的な栄養基準と照らして確認する。

**3. 食品データの入手先と取り込み方法**

食品データには、文部科学省が公開する「日本食品標準成分表（八訂）増補2023年」を使用する。

- 公式資料：https://www.mext.go.jp/a_menu/syokuhinseibun/mext_00001.html
- 食品成分データベース：https://fooddb.mext.go.jp/

初期開発では、公式Excelデータから使用する食品の番号、食品名、エネルギー、タンパク質、脂質、炭水化物に対応する成分項目を抽出し、CSV形式に整形する。その後、Railsのseedsまたはインポート処理を使ってデータベースに登録する。

食品の成分値は可食部100gあたりの値を基本とし、記録された摂取重量に応じて栄養素を換算する。食品データの出典と版を管理し、公式の正誤表も確認する。初期版では、必要な成分値を確認できた食品から段階的に対応する。

## 8. このアプリの懸念点とその対策

### 懸念点①：栄養素の計算や目標値の精度

- **何が問題になりそうか：**
  食品ごとの栄養素の情報が不十分だったり、ユーザーに合わない摂取目標が提示されたりすると、適切な食事管理につながらない可能性がある。

- **なぜそう思うか：**
  食品によって含まれる栄養素が異なるうえ、ユーザーの体格・目標・生活スタイルによって必要な摂取量も異なるため、正確な食品データと適切な計算方法が必要になるから。

- **そのために考えている対策：**
  信頼できる栄養成分データを利用し、食品の摂取量に応じて栄養素を計算する。目標値は根拠のある栄養基準や計算方法に基づいて設定し、推定値であることも明示する。また、初期開発では対応できる食品・栄養素から実装し、段階的に対象を広げる。

### 懸念点②：開発範囲が広く、完成までに時間がかかる可能性

- **何が問題になりそうか：**
  栄養素の管理、食事提案、進捗グラフ、モチベーションサポートなどを一度に実装しようとすると、開発が長期化する可能性がある。

- **なぜそう思うか：**
  各機能にデータの準備や計算処理、画面の実装が必要になるため。

- **そのために考えている対策：**
  まずは目標設定、食事記録、栄養素の自動集計という中心的な機能を完成させる。その後、進捗の可視化や食事提案などを段階的に改善・拡張する。

## 9. 今後の展開・発展の方向性

### 9-1. 継続利用によって生まれる価値

ユーザーが毎日の食事や体重・体脂肪率などを記録することで、日々の摂取カロリー・PFCの状況や身体の変化を振り返れるようにする。

現在の体重・体脂肪率と目標体重・目標体脂肪率を記録し、それぞれの現在値と目標値の差や推移をグラフで確認できるようにする。また、お気に入り食品、最近使った食品、前日の食事コピーによって記録の手間を減らし、進捗グラフやメッセージを通じて、食事管理を継続しやすくする。

食材・料理の提案やAIによる記録補助などは、基本的な食事記録と栄養管理を実装した後、必要性を確認しながら段階的に追加する。

---

### 9-2. 今後追加したい機能

以下の機能は、MVPの完成後に必要性や実装コストを考慮しながら、段階的に追加する。

**① 幅広い栄養素の管理**

PFCに加えて、食物繊維、食塩相当量、ビタミン類、ミネラル類なども管理対象に広げる。信頼できる食品データを取得できる栄養素から対応する。

**② 食材・料理の提案**

ユーザーの目標や生活スタイル、過去の食事記録、栄養摂取状況を参考に、目標に合った食材や料理を提案できるようにする。

**③ 進捗の可視化の拡張**

食事、栄養摂取量、体重、体脂肪率などの長期的な推移をグラフで確認し、過去と現在を比較できるようにする。

**④ モチベーションサポートの拡張**

目標イメージなどのビジュアルや、継続状況に応じたメッセージを活用し、ユーザーが自分の取り組みを振り返りやすくする。

**⑤ ユーザー同士の交流機能**

友人と食事管理の進捗を共有したり、お互いの努力を認め合ったり、励まし合ったりできる機能を追加する。

**⑥ AIを活用した機能**

AIによる食事記録の補助や、食事履歴を活用した食材・料理の提案などを検討する。

## 10. 技術選定（手段としての技術）

### 10-1. 使用予定の技術

- **フレームワーク：** Ruby on Rails
- **データベース：** MySQL
- **デプロイ先：** Railway（候補）
- **使用予定ライブラリ：**
  - Devise：ユーザー登録・ログイン機能
  - Chartkick：体重・体脂肪率・栄養摂取状況などのグラフ表示

### 10-2. 技術選定の比較検討

| 技術 | 採用・不採用 | 理由 |
|---|---|---|
| Ruby on Rails | 採用 | スクールで学習してきた技術を活かし、アプリの開発を進めるため。 |
| MySQL | 採用 | 既存のRails課題で使用しているデータベースであり、ユーザー情報や食事記録などの関連データを管理するため。 |
| Railway | 採用予定 | Railsアプリを公開するための候補。実際のデプロイ時に設定や料金を確認する。 |
| Devise | 採用予定 | ユーザー登録・ログイン機能を実装するため。 |
| Chartkick | 採用予定 | 記録データをグラフで表示するため。 |
| React / Next.js | 初期開発では採用しない予定 | まずはRailsを中心にMVPを完成させ、開発範囲が広がりすぎないようにするため。 |

※ ライブラリの導入前に、使用するRuby・Railsのバージョンとの互換性を確認する。

### 10-3. 今回チャレンジしたい点

- 食事記録から複数の栄養素を自動集計する仕組みの実装
- 体重・体脂肪率・栄養摂取状況などの進捗を可視化する仕組みの実装
- ユーザーの目標や生活スタイルに合わせて食材・料理を提案する仕組みの実装
- 栄養管理の結果を、ユーザーの継続につながるメッセージやビジュアルで伝える仕組みの実装

### 10-4. 不安な点

- 幅広い栄養素を扱うための食品データの準備と計算精度
- ユーザーの目標に応じた栄養摂取目安の算出方法
- 食材・料理の提案に使用するデータの準備と管理
- Railwayへのデプロイと本番環境でのデータベース接続
- 開発範囲を適切に管理し、MVPを完成させること
